LAYER 1

The Vault — Markdown Files as Your Knowledge Base

At its core, your memory system is just a folder of .md (markdown) files. That's it. No special software required. Every AI tool — Claude, ChatGPT, Cursor, Claude Code — can read markdown files natively.

The trick is structure. Without structure, you have a pile of notes. With structure, you have a knowledge base.

Here's a starting point — 12 folders that cover most businesses. You don't need all of them. Start with the ones that make sense for you and add more as you go:

vault/
├── clients/           ← One folder per client. Everything about them lives here.
├── leads/             ← People you're talking to but haven't closed yet.
├── offers/            ← Your offers, pricing, positioning, sales pages.
├── content/           ← Content you've created or plan to create.
├── systems/           ← SOPs, processes, how your business runs.
├── knowledge/         ← Frameworks, swipe files, reference material.
├── products/          ← Your products, tools, SaaS projects.
├── transcripts/       ← Call recordings, meeting notes, voice memos.
├── decisions/         ← What you decided, why, and what you rejected.
├── inbox/             ← Quick captures. Process weekly.
├── personal/          ← Private stuff. Values, stories, timeline.
└── archive/           ← Done or dead. Searchable but out of the way.

The rule: when you sit down to work on something, you go to its folder. Client work? clients/jane-doe/. Building an offer? offers/new-coaching-program/. The folder IS the workspace.

Adding YAML frontmatter to your files makes them even more powerful — it lets tools like QMD (Layer 2) understand what each file IS, when it was created, and what it relates to. But it's not required to start.

---
title: Jane Doe - Discovery Call Notes
type: transcript
client: jane-doe
date: 2026-03-15
tags: [discovery, ai-readiness, high-intent]
---

# Discovery Call — Jane Doe
...your notes here...
LAYER 2

QMD — Semantic Search Over Everything You Know

Once you have a vault of markdown files, the next question is: how do you FIND things? Ctrl+F doesn't cut it when you have thousands of files.

QMD is a local search engine built specifically for markdown knowledge bases. It runs on your machine — nothing goes to the cloud. It indexes your files and lets you search by keyword (BM25) or by meaning (semantic/vector search).

Why this is groundbreaking:

  • It runs 100% locally. Your knowledge never leaves your machine.
  • It understands meaning, not just keywords. Search "how to handle client objections" and it finds your call transcript where you handled one — even if those exact words aren't in the file.
  • It has an MCP server, which means Claude Code and other AI tools can search your entire vault mid-conversation. Your AI doesn't just read one file — it searches across everything you know.
  • It indexes 34,000+ documents in seconds. No lag. No cloud dependency.

To get started:

Get QMD

Install QMD globally with one command:

bun install -g https://github.com/tobi/qmd

Point it at your vault folder and run qmd embed to index everything. It runs completely standalone — no cloud, no dependencies beyond Bun.

QMD also has an MCP server, which means Claude Code can search your entire vault mid-conversation. Your AI doesn't just read one file — it searches across everything you know.

LAYER 3

The Knowledge Graph — Relationships Between Everything

This is the frontier layer. Layers 1 and 2 give you storage and search. Layer 3 gives you connections.

A knowledge graph is a simple SQLite database that tracks relationships between entities — people, companies, projects, decisions — with temporal data (when things happened, how relationships changed over time).

For example:

  • Which clients did I talk to this week? (temporal query)
  • Who introduced me to this person? (relationship traversal)
  • What decisions did I make about this project, and when? (decision timeline)
  • Which relationships are going cold? (drift detection)

This layer is powerful but optional to start. Get Layer 1 and Layer 2 running first. The graph becomes valuable when you have enough data flowing through the system that you need to understand relationships between things, not just find individual files.

The YAML frontmatter from Layer 1 feeds into this — tags, dates, client names, and relationship markers in your files become nodes and edges in the graph automatically.

START HERE

30 Minutes to Your First Working Vault

  1. Create a folder called vault/ anywhere on your machine.
  2. Add 5-6 of the subfolders from the structure above — whichever match your business.
  3. Move your existing notes, docs, and transcripts into the right folders. Don't overthink it.
  4. Install QMD and point it at your vault. Run qmd embed.
  5. Install the QMD MCP server for Claude Code.
  6. Open Claude Code in your vault directory. Ask it something about your business. Watch it search your files and answer with context.
  7. Add YAML frontmatter to new files as you create them. Don't go back and retrofit old ones — it's not worth the time.

That's it. You now have a searchable, AI-accessible knowledge base. Everything you add from here compounds.
